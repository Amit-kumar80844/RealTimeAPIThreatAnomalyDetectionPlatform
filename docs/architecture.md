# System Architecture & Data Pipeline Specification

## 1. Overview
The **Real-Time API Threat & Anomaly Detection Platform** is a distributed, low-latency streaming pipeline that continuously ingests web API gateway logs, evaluates sliding window security metrics, detects malicious traffic patterns (DDoS, Brute-Force, Endpoint Exhaustion, Large Payloads), and persists structured events into a distributed analytical warehouse (Hadoop HDFS / Apache Hive).

## 2. Ingestion Layer (Apache Kafka)
- **Topic**: `api-raw-logs`
- **Partitions**: 3 (hashing partition key: `client_ip`)
- **Ordering Guarantee**: Kafka guarantees absolute message ordering per partition. By partitioning on `client_ip`, all HTTP events generated by a specific client IP arrive in order at the same Spark executor stream reader partition.
- **Retention**: 24 hours ring buffer.

## 3. Stream Processing Layer (Apache Spark Structured Streaming)
- **Micro-batching**: 10-second micro-batch intervals.
- **Watermarking**: 10 minutes (`withWatermark("event_timestamp", "10 minutes")`) to handle out-of-order network logs without state explosion.
- **Stateful Sliding Windows**: $W=60\text{ seconds}$ duration, sliding every $S=10\text{ seconds}$.

## 4. Analytical Warehouse Layer (Hadoop HDFS & Apache Hive)
- **Raw Log Storage**: HDFS `/user/hive/warehouse/api_security.db/raw_api_logs` in compressed Snappy Parquet format, partitioned by date (`dt=YYYY-MM-DD`).
- **Threat Alerts Table**: Hive table `api_security.threat_alerts` stored as optimized ORC format, enabling high-performance column pruning and predicate pushdowns for post-incident security investigations.
